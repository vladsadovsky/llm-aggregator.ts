# Build Notes

- V2 0.6/0.7 feature flags + usage ledger (2026-08-01): `shared/featureFlags.ts` (dependency-free) declares the known experimental flags with metadata; `isFeatureEnabled(map, id)` is the single resolver both runtimes call — default-off, unknown ids fail closed but are preserved for forward compat. `AppSettings.experimentalFeatures` (id→boolean, bounded in the zod contract) persists them; `electron/services/featureFlags.ts` enforces in main independently of the renderer (`assertFeatureEnabled` throws the new `feature-disabled` code). `electron/services/llm/usageLedger.ts` (0.7, INV-COST) is one metered sink: call counts + token totals keyed by capability/provider/model/local, with an approximate cost from a dated public-pricing table (unknown model → "cost unavailable", local → zero) and `estimateBatchCost` for pre-fan-out warnings. It records no prompt/response text, ids, urls, or secrets. `tokenTracker` is now a thin facade over the ledger (IPC `ai:getTokenStats` shape unchanged), and both the OpenAI and Anthropic providers record one entry per physical call (Anthropic completions were previously unmetered). New IPC error code: `feature-disabled`. 16 unit tests added. Deferred/tracked: the Settings → Experimental Features UI and surfacing session usage in Application Status (renderer wiring for a later group); per-call failure/cancel metering and the per-session hard-limit override.
- V2 P0-I LLM capability split (2026-08-01): the universal `LLMProvider` is split into declared capability interfaces `CompletionProvider` / `EmbeddingProvider` (INV-LLM), so requesting an embedding no longer traps at runtime inside a completion-only provider's `embed()`. Registry descriptors now carry an immutable `capabilities: { complete, embed, streaming, local }` (OpenAI: complete+embed; Anthropic: complete only), exposed to the renderer via `aiListProviders` so the UI can gate features by capability rather than provider name. `providerFactory` adds `getCompletionProvider()` and `getEmbeddingProvider()` — the embedding factory validates the `embed` capability BEFORE constructing or loading a key, throwing a clear "does not support embeddings" message instead of letting Anthropic's `embed()` throw deep in a call; `embeddingService` now uses it. `getProvider()` is retained for completion consumers. `providerSupports(id, capability)` is the pure check (unknown → false). 12 unit tests added (providerRegistry, providerFactory). Deferred within G5 and tracked as remaining Phase 0 work: the `@anthropic-ai/sdk` migration (P0-I step 5), the Ollama/Azure adapters (0.1), the generic batch runner (0.2), and the centralized session usage ledger/guard replacing `tokenTracker` (0.7). `tokenTracker` is unchanged for now.
- V2 P0-G secret hardening + verified legacy migration (2026-08-01): the safe-storage backend now rejects Linux `basic_text` (INV-SECRET) — `SafeStorageCrypto` gained an optional `getSelectedStorageBackend()`, and on Linux a `basic_text` selection is treated as unavailable for both read and write (a stable `SAFE_STORAGE_INSECURE_BACKEND` warning; save throws) rather than being presented as encrypted storage. The encrypted envelope is now written through the P0-D atomic primitive with last-known-good and a decrypt-before-promote validator, so a save that cannot be read back never replaces a good envelope. Startup no longer only orphans `secrets.json` as cleartext: `secrets/legacyMigration.ts` reads the known keys, merges them into encrypted storage WITHOUT overwriting a valid stored value, persists, reloads and compares keyed SHA-256 fingerprints, and only then unlinks the plaintext (and any prior `.orphaned.bak`). If secure storage is unavailable, a file is unparseable, or verification fails, the plaintext is left untouched and a warning is surfaced (`LEGACY_FILE_ORPHANED` / `LEGACY_MIGRATION_FAILED`); a successful run reports `LEGACY_MIGRATED` and notes that file deletion cannot guarantee erasure from SSD wear-leveling or cloud-sync history. `initSecretsStorage` now runs the migration instead of the rename-only sweep (`legacyCleanup.ts` is retained for its constants and remains unit-tested). No secret value is ever logged. 21 unit tests added/updated (Linux basic_text, atomic decrypt-before-promote, and the full migration matrix). Manual Linux keyring-vs-basic_text and Windows install/restart/upgrade checks remain user-run.
- V2 P0-E/F import containment + bulk durability (2026-08-01): shared-link transport is now bounded and contained (INV-NET). `import/remoteUrlPolicy.ts` (pure) requires HTTPS, no credentials, the default port, and an exact registered API host, and redacts the final path token in logs/errors. `conversationFetcher.fetchJson` does manual redirect handling — every hop is re-validated against the host allowlist, capped at 3 hops, a 20 s overall timeout, and a 16 MiB decoded-body ceiling — surfacing structured codes (invalid-url, redirect-disallowed, redirect-limit, timeout, response-too-large, http-error, format-changed) that `sharedLinkImportService` maps to coded IpcErrors so friendly messages survive the bridge; share tokens are no longer logged. The Gemini hidden window now uses a unique non-persistent partition, denies popups and all permission requests on its own session, and blocks navigation off the Gemini render hosts (a sign-in redirect for a private/expired link is denied and yields no content). Bulk import (INV-IMPORT): preview ids are `crypto.randomUUID()`, previews expire on a 10-minute unref'd TTL sweeper, and a commit claims its preview (rejecting a double commit). `commitArchiveImport` is now async and cancellable — it takes an AbortSignal, treats each conversation as the durable unit (writing its pairs then saving threads.json atomically before moving on), yields to the event loop every 64 pairs so main stays responsive, stops before the next durable unit on cancel without promoting a half-written thread (its pairs remain recoverable on re-run via origin_id), and returns a `cancelled` flag. `import:archiveCancel` now aborts an in-flight commit rather than only dropping the preview. Deferred within P0-F (tracked): preview owner/webContents binding, selection by an opaque previewThreadId (still keyed on provider sourceId), and shard-manifest byte/count budgets. 31 unit tests added (remoteUrlPolicy, fetchJsonPolicy via a fake net, bulkImport cancellation/incremental-save); the live-provider smoke and bulk-import cancel E2E remain user-run.
- V2 P0-C canonical IPC contracts + sender guard (2026-08-01): every privileged channel now flows through one validated registrar (`electron/ipc/registerValidatedHandler.ts`). Channel strings are centralized in `shared/contracts/channels.ts` (dependency-free, imported by preload/main/tests) and each channel has a canonical `zod` argument schema in `shared/contracts/*`; the `channelArgs` registry uses `satisfies Record<Channel, …>` so a channel added without a schema fails the build (compile-time parity). Before any service runs, the wrapper rejects untrusted senders (`INV-IPC`: `event.sender` must equal the main window's webContents, `event.senderFrame` must be its `mainFrame`, and the frame origin must match the app origin) and parses the argument tuple (strict objects, bounded strings/arrays, finite numbers, traversal-shaped ids rejected — `INV-PATH`). Failures cross the bridge as stable coded errors (`invalid-sender`, `invalid-payload`, `not-found`, …) with no stack, path, secret, or provider body (`INV-OBS`); unexpected throws are logged main-side only and surface as a generic `internal` code. Success return shapes are unchanged, so the renderer is untouched except that `preload.ts` now routes through channel constants and decodes coded errors into clean `Error` objects carrying `.code`. New prod dependency: `zod`. Per-domain user-facing error messages (import/secret/LLM) are hardened to specific codes in their own later groups; until then a service throw shows the generic message. 48 unit tests added (`ipcSenderPolicy`, `ipcContracts`, `ipcRegistrar`). Remaining manual/E2E gate: an iframe/unexpected-frame privileged-call rejection E2E (deferred to the user-run suite).

- Shared-link import architecture research (2026-07-25): Google's Gemini Help currently documents public conversation links as `https://g.co/gemini/share/<id>`; observed direct links also include `https://share.gemini.google/<id>`, while `https://gemini.google.com/share/<id>` is a legacy form. The short-term compatibility patch accepts the observed direct host in addition to the legacy path, but URL-prefix matching is not a durable provider contract and does not cover the documented short URL.
	- Proposed direction: replace the import service's exact-host `detectProvider(rawUrl)` gate with a two-stage pipeline: first parse and normalize the pasted value with the standard `URL` API, then resolve an approved short-link alias and classify the resulting canonical URL through a shared provider registry. Each provider adapter owns URL matching, share-reference parsing where needed, and provider-specific import. Gemini's rendered-page importer receives the validated canonical URL directly and must not depend on extracting a Gemini share ID; ChatGPT and Copilot keep deterministic ID parsing for their JSON API import paths.
	- Security policy: accept known aliases permissively but do not make the hidden Gemini `BrowserWindow` an unrestricted browser. Require HTTPS, reject credentials, non-default ports, malformed and local/private-network targets, cap redirects, record the redirect chain, and permit only registered provider/shortener destinations. During Gemini rendering, use Electron `will-navigate` and `will-redirect` to block unapproved main-frame navigation and deny `window.open`; retain sandboxing, context isolation, and disabled Node integration. Electron exposes the needed redirect/navigation events and final URL inspection through `webContents`.
	- Diagnostics: return structured failures (`invalid-url`, `unsupported-provider`, `redirect-disallowed`, `private-or-expired`, `format-changed`) rather than the current generic unrecognized-link message. Redacted development logging may record unknown redirects from otherwise trusted providers without retaining public-link tokens.
	- Test matrix: table-drive direct, legacy, and official-short Gemini forms; mocked redirect resolution; redirect-to-untrusted-host rejection; retained ChatGPT/Copilot routes; malformed URLs, credentials, non-default ports, and private-IP rejection; and Gemini rendering with a canonical URL but no parsed share ID.
	- Delivery stages: first add `g.co/gemini/share/...` through controlled resolution and update the UI/documentation to say “public share link” with examples rather than fixed supported-host copy. Then introduce the provider registry/resolver with the security policy and migrate ChatGPT, Copilot, and Gemini adapters. Do not transform a Gemini URL by hand: resolve it, validate the final provider destination, then render that canonical location.
