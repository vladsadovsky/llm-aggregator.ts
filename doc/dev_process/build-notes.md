# Build Notes

- `npm run build` runs `vue-tsc --noEmit && vite build`; type errors can block config verification.
- Use `npx vite build` to validate Vite/Rollup config behavior independently of TS typecheck failures.
- Vite CJS deprecation warning in this repo was resolved by renaming `vite.config.ts`/`vite.config.server.ts` to `.mts` and updating script references.
- QA creation IDs were minute-granularity and caused collisions during rapid create flows; switched to second+millisecond IDs with filesystem collision check.
- UX preference for this repo: optimize QA entry for high-throughput streams (keep primary create actions always visible and minimize scrolling/click friction).
- Electron Playwright coverage uses a temporary isolated working directory in `tests/e2e/electron.fixture.ts` so e2e runs do not write `threads.json` or `archive/` into the repo root.
- Playwright usage is now intentionally split between stable npm scripts in `package.json` (`test:e2e`, `test:e2e:debug`, `test:e2e:ui`, `test:e2e:report`) and explicit ad hoc CLI examples in `README.md` and `BUILD.md` for single-spec and filtered runs.
- When a documented Playwright command becomes a reusable repo-specific workflow, prefer a checked-in helper under `scripts/` over leaving the exact command line only in documentation. Current helper: `scripts/playwright-electron.sh`.
- Visual snapshot maintenance now has explicit scripts: `test:visual` to run visual regression checks and `test:visual:update` to accept the current UI as the new approved baseline when that change is intentional.
- Documentation was consolidated so README.md is now the canonical user/developer guide; BUILD.md is a short pointer to avoid duplicated instructions drifting.
- LLM Lens is now an optional, default-disabled feature (2026-07-25). `lensEnabled` is persisted in settings; when disabled, the panel, toolbar button, command-palette command, native View-menu entry, and reserved bottom space are absent. README is the canonical Lens usage guide; `USAGE.md` links to it rather than duplicating Lens instructions.
- LLM Lens design and usage review completed (2026-07-25): `doc/plans/LLM_Lens_Design_Usage_Review_2026-07-25.md` records purpose, current retrieval architecture, actual OpenAI-only operational requirement, documentation defects, and prioritized improvements. This review did not change application behavior.
- Export / Import feature added (2026-03-15): format logic is split from file transport in `electron/services/qaExportFormatService.ts`, `qaImportFormatService.ts`, `fileExportService.ts`, `fileImportService.ts` so future non-file targets (OneNote, etc.) can reuse the formatter/parser. IPC channels `export:qa`, `export:thread`, `import:file` added. UI entry points: Export button in QAContentPanel (selected QA), Export button per thread row in ThreadsPanel, keyboard shortcut `X` (export), `Ctrl+O` (import), and command palette entries. On import: IDs/timestamps are always regenerated (never overwrite); `original_id` and `original_timestamp` preserved as auxiliary fields; version mismatch uses best-effort with per-item warnings shown in toast + summary dialog.
- AI / LLM features merged (2026-03-xx from eveselov/dev branch post-fork): Added LLM Lens (InsightsPanel), archive health report (HealthReportDialog), AI metadata generation (topic, status, confidence, summary, relatedIds, concepts), vector embeddings + semantic search, confidence annotations (AnnotationDialog), and secrets management (API key storage). New services: `annotationService`, `embeddingService`, `healthService`, `insightsService`, `metadataService`, `secretsService`, `llm/openaiProvider`, `llm/providerFactory`, `llm/tokenTracker`, `llm/types`. New components: `AnnotationDialog.vue`, `HealthReportDialog.vue`, `InsightsPanel.vue`. New dependency: `openai@^6`. Global search (across archive, not just current thread) with scope toggle and save-as-thread added to QAListPanel + ThreadsPanel. `src/api-mock.ts` updated to include `llmProvider`, `llmModel` defaults and no-op stubs for all new AI API methods.
- Native Windows MSI packaging added with `npm run electron:build:msi`. The MSI is assisted, per-user, and uses pinned upgrade code `70DA883D-10E1-456D-BFBB-6E77AAE20DFC`; signing and per-machine deployment are deferred. New Windows archives default to an existing OneDrive root under `Documents\LLM-Aggregator`, falling back to `%USERPROFILE%\Documents\LLM-Aggregator`; users can override this in Settings.
- AI settings model picker now uses provider/model catalog plumbing (`ai:listProviders`, `ai:listModels`) backed by `electron/services/llm/providerRegistry.ts` and `electron/services/llm/modelCatalogService.ts`. Phase 1 behavior: OpenAI models are fetched dynamically when an API key is available, then cached in `model-catalog-cache.json`; UI falls back to cached/static curated models with warning text when fetch fails. The provider registry is intended as the extension point for future OpenAI-compatible providers and local gateways.
- OpenAI settings UX follow-up: `ai:listModels` now accepts an optional in-memory OpenAI API key override so model discovery works immediately after typing a key in Settings (before Save). Settings also disables non-enabled providers in the provider picker and refreshes model catalog automatically after a successful connection test.
- Anthropic provider support implemented: added `electron/services/llm/anthropicProvider.ts` and wired `providerFactory` to instantiate it when `llmProvider=anthropic`. Model catalog now supports dynamic Anthropic model discovery through `GET /v1/models`, including in-memory key override in `ai:listModels` so refresh works before saving settings. Settings exposes Anthropic as enabled provider and auto-refreshes model list after successful Anthropic connection test. Current limitation: embeddings and semantic-index generation remain OpenAI-only in this app provider path; UI now shows this explicitly and disables the embeddings generation button when Anthropic is selected.
- Secrets storage Phase 1 groundwork: settings schema now includes `allowDevEnvSecrets` and `devEnvSecretPrefix` (default `LLM_AGG_`), with development-only controls in `SettingsDialog.vue`. This is plumbing only: it introduces explicit, persisted intent for env-based secret override without changing existing secrets backend behavior yet. **Superseded** by the entry below — `devEnvSecretPrefix` was subsequently removed.
- Secrets storage V1 (Steps 1–5) implemented — full spec in `doc/plans/Secrets_Storage_Design_and_Implementation.md`. API keys are no longer stored in clear text: `electron/services/secrets/` adds a `SecretBackend` chain (`env` dev override → `safe-storage`), a resolver with fixed precedence, and a status projection that gives the renderer presence/masked-preview/provenance instead of key values. Electron `safeStorage` replaces the plan's separate keychain + encrypted-file tiers (OS holds the key; no native dependency; stays synchronous so the 11 `getProvider()` call sites are unchanged). `secrets:load` now returns `SecretsStatus`, `secrets:save` takes a partial update, and `secrets:recheck` / `secrets:devEnvVarNames` are new. `devEnvSecretPrefix` was dropped — the prefix is the fixed constant `LLM_AGG_`. The env override requires both the setting and `!app.isPackaged`. Legacy plaintext `secrets.json` is **not read**; it is renamed to `secrets.json.orphaned.bak` on startup and users re-enter keys. Step 6 (true migration) is deliberately deferred. Also fixed while in the file: unguarded model-catalog cache write, an unreachable Anthropic branch, and the dual-key model-discovery override collapsed to one scoped `apiKeyOverride`. 28 unit tests added.
